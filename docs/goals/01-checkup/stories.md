## Command conventions and shared checks

All commands below are for a later authorized implementation session, run from the identified clean checkout on the named host unless otherwise stated. They are not commands to execute during this planning session. No `--upgrade`, automatic lock updates, GC, installer replacement or routine state-version changes are implied.

Before use, bind these non-secret parameters to discovered values in that session: `CHECKUP_COMMIT` (approved full commit), `MAC_OLD`/`VPS_OLD` (canonical pre-change closure), `MAC_OLD_GEN`/`VPS_OLD_GEN` (generation numbers), `MAC_NEW`/`VPS_NEW` (canonical built closure), `CHECKUP_LOGIN_USER`, `CHECKUP_VPS` (explicitly authorized SSH target), and test domain/host/account identifiers. Use quoted variables. Do not put passwords, tokens, hashes or private-key contents in variables, command arguments, source trees or evidence. Disable shell tracing and session recording when handling authentication. Record exit status and timestamp with each check. A failed command blocks its gate.

Only metadata and sanitized output may be retained. Inspect logs for secret values before pasting; redact values while preserving error type, location and warning text. Never dump whole evaluated configurations, environment files, mail contents, private keys or secret-bearing unit definitions. No flake source materialization/evaluation/build occurs until US-02 removes embedded credentials from the candidate source. Historical Git objects and old store closures are not erased by that change; record exposure/rotation needs without dumping them.
